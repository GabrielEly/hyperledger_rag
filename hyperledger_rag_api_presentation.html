Hyperledger RAG

Nova apresentação com as melhorias do projeto, foco na API e no fluxo de RAG local para consultas à documentação Hyperledger Fabric.

Arquitetura limpa

Separação clara entre core, application e infrastructure.

API REST

Endereços para consulta, monitoramento, crawling e métricas.

RAG otimizado

Recuperação com FAISS, geração com TinyLlama e enriquecimento com ontologia.

Melhorias entregues

  • Refatoração para API mais robusta e startup controlada com lifespan.
  • Cache de respostas para reduzir latência em consultas repetidas.
  • Streaming SSE em /api/v1/query/stream para resposta token-a-token.
  • Monitoração de saúde em /api/v1/health e métricas em /api/v1/stats.
  • Job de crawling e ingestão de documentos via endpoint protegido /api/v1/crawl.

O que a API oferece hoje

Query

POST /api/v1/query — pergunta ao RAG e recebe resposta completa.

Streaming

POST /api/v1/query/stream — resposta incremental para UI em tempo real.

Admin

POST /api/v1/crawl — inicia recrawling e reindexação.

Monitoramento

GET /api/v1/health — verifica a saúde da API.

Fluxo da requisição RAG

  1. Recebe query JSON no endpoint /api/v1/query.
  2. Verifica cache e retorna resultado se existir.
  3. Enriquece query com ontologia Hyperledger, se habilitado.
  4. Executa busca no indice FAISS.
  5. Gera resposta com TinyLlama usando contexto recuperado.
  6. Cachea a resposta para consultas futuras.
Resultado

Maior precisão, menor latência e auditoria de origem com referências de documentação.

API pública e autenticação

O serviço usa variáveis de ambiente definidas em .env e Settings para controlar:

  • API_HOST e API_PORT
  • API_PREFIX (/api/v1)
  • API_KEY_REQUIRED e API_KEYS
  • RATE_LIMIT e CACHE

Se API_KEY_REQUIRED=true, envie X-API-KEY em todas as requisições protegidas.

Exemplo de consulta

# Corpo JSON enviado ao endpoint { "query": "O que é um chaincode no Hyperledger Fabric?", "model_version": "v1", "use_cache": true, "use_ontology": true, "top_k": 4, "stream": false }
# Exemplo curl curl -X POST "http://localhost:8000/api/v1/query" \ -H "Content-Type: application/json" \ -H "X-API-KEY: SUA_CHAVE_AQUI" \ -d '{"query":"O que é um chaincode no Hyperledger Fabric?","use_cache":true,"use_ontology":true,"top_k":4}'

Execução do crawling via API

Este projeto permite iniciar um novo crawling diretamente pela API:

# Requisição para recrawling POST /api/v1/crawl { "max_pages": 50, "force_refresh": false }
Atenção

O endpoint de crawling exige autenticação e atualiza o índice FAISS no caminho configurado em VECTOR_DB_PATH.

Monitoramento e métricas

Health

GET /api/v1/health — verifica status do RAG, cache e índice.

Valor

Permite observabilidade e planejamento de recrawling antes de novas consultas.

Melhorias técnicas

  • Startup controlada pelo lifecycle do FastAPI.
  • Cache in-memory para consultas idênticas.
  • Integração com ontologia Hyperledger para melhor entendimento.
  • Modelo local TinyLlama e embeddings all-MiniLM-l6-v2.
  • FAISS como motor de busca vetorial offline.
