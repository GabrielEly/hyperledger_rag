Hyperledger RAG

Este guia apresenta as funcionalidades do sistema RAG e os endpoints da API REST disponíveis no projeto.

1. Funcionalidades do RAG

  • Crawler: coleta a documentação do Hyperledger Fabric da web.
  • Indexação vetorial: gera embeddings e armazena em FAISS.
  • RAG local: usa modelos locais para responder perguntas com contexto recuperado.
  • Ontologia: enriquece queries com contexto de Hyperledger.
  • Cache: evita reprocessar perguntas idênticas.

2. Como o sistema funciona

  1. Crawling: extrai páginas da documentação do Hyperledger Fabric.
  2. Ingestão: divide o texto em chunks e converte em vetores.
  3. Busca: consulta o índice FAISS para encontrar trechos relevantes.
  4. Geração: envia o contexto ao modelo LLM local para gerar a resposta.

3. Pré-requisitos

  • Python 3.10 ou superior.
  • Dependências instaladas via pip install -r requirements.txt.
  • Índice FAISS gerado em faiss_index_v2 antes de realizar consultas no RAG.

4. Iniciar a API

O arquivo principal da API é src/api/main.py. Para iniciar a API em desenvolvimento:

uvicorn src.api.main:app --reload --host 0.0.0.0 --port 8000

Valores padrão de configuração:

  • API_HOST: 0.0.0.0
  • API_PORT: 8000
  • API_PREFIX: /api/v1
Importante: por padrão a API exige cabeçalho X-API-KEY se API_KEY_REQUIRED estiver habilitado.

5. Endpoints principais

5.1 POST /api/v1/query

Faz uma pergunta ao RAG e retorna a resposta gerada.

Payload JSON:

{
  "query": "O que é um chaincode no Hyperledger Fabric?",
  "model_version": "v1",
  "use_cache": true,
  "use_ontology": true,
  "top_k": 4,
  "stream": false
}

Resposta JSON:

{
  "query": "O que é um chaincode?",
  "response": "Um chaincode é um programa (smart contract)...",
  "sources": [
    {
      "title": "Hyperledger Fabric Documentation",
      "url": "https://hyperledger-fabric.readthedocs.io",
      "relevance_score": 0.9,
      "snippet": null
    }
  ],
  "relevance_score": 0.85,
  "retrieval_time_ms": 50,
  "generation_time_ms": 1230,
  "total_time_ms": 1280,
  "from_cache": false,
  "ontology_entities": ["chaincode", "peer", "transaction"],
  "model_version": "v1"
}

5.2 POST /api/v1/query/stream

Gera uma resposta em streaming via Server-Sent Events (SSE). Útil para interfaces que exibem resposta token por token.

Reutiliza o mesmo payload de /api/v1/query.

5.4 POST /api/v1/crawl

Inicia o processo de crawling e reindexação da documentação.

{
  "max_pages": 50,
  "force_refresh": false
}

5.5 GET /api/v1/health

Verifica a saúde da API e dos serviços internos.

5.6 GET /api/v1/stats

Retorna estatísticas de uso e métricas básicas.

5.7 GET /api/v1/index-info

Retorna informações do índice FAISS, como número de documentos e dimensões.

5.8 GET /

Retorna nome da API, versão e status.

6. Exemplo de uso com curl

curl -X POST "http://localhost:8000/api/v1/query" \
  -H "Content-Type: application/json" \
  -H "X-API-KEY: SUA_CHAVE_AQUI" \
  -d '{
    "query": "O que é um chaincode no Hyperledger Fabric?",
    "use_cache": true,
    "use_ontology": true,
    "top_k": 4
  }'

7. Exemplo de uso em Python

import requests

url = "http://localhost:8000/api/v1/query"
headers = {
    "Content-Type": "application/json",
    "X-API-KEY": "SUA_CHAVE_AQUI"
}
payload = {
    "query": "Explique o conceito de chaincode no Hyperledger Fabric.",
    "use_cache": True,
    "use_ontology": True,
    "top_k": 4
}
response = requests.post(url, json=payload, headers=headers)
print(response.status_code)
print(response.json())
Dica: se a API estiver configurada sem X-API-KEY, basta remover o cabeçalho do request.

8. Exemplos de instruções de uso

Use perguntas objetivas e específicas para obter melhores respostas:

  • Bom: "O que é um chaincode no Hyperledger Fabric?"
  • Bom: "Como funciona o processo de endorsement em Fabric?"
  • Ruim: "Fale sobre Fabric"

9. Execução do RAG via CLI

Além da API, há uma interface CLI no arquivo src/main.py:

python src/main.py crawl --pages 50
python src/main.py ask "O que é um chaincode no Hyperledger Fabric?"

O comando crawl gera ou atualiza o índice em faiss_index_v2.

10. Observações finais

  • O índice vetorial deve existir antes das consultas via API.
  • A API usa um modelo local TinyLlama e embeddings locais para minimizar dependências externas.
  • Os endpoints de administração exigem autenticação quando o modo de API key está ativo.
